How {{ site_name }} processes a query, from form submission to result.

The query lifecycle

When you submit a tool's form, your input passes through validation, anti-bot checks, and usage limits before being accepted. The query then enters a queue and is processed in the background by a dedicated worker — this prevents slow network analyses from blocking navigation. While this happens, the page shows a status bar that is updated in real time (via Server-Sent Events, with automatic fallback to periodic polling if the real-time connection is unavailable).

Possible query statuses are:

  • Awaiting validation / Checking CAPTCHA — pre-queue checks.
  • Query queued / Processing / Querying services — the task is in the queue or running.
  • Analyzing results / Generating report — collected data is being organized.
  • Creating public page — when applicable, the shareable page is being generated.
  • Completed — the report is ready.
  • Failed / Expired / Cancelled — the query could not be completed; the reason is shown on screen.

Cache and reuse

To avoid overloading the queried services and generating duplicate reports, each tool has its own TTL (time-to-live). If someone has already queried the same input recently, you receive the existing result instantly instead of waiting for new processing. After the TTL expires, a new query is allowed normally.

Public pages and SEO

Successfully completed queries for public resources may generate a shareable page with a predictable URL (e.g., /dns/example.com/). Not every query is indexed by search engines: results with errors, empty results, duplicates, queries involving private networks, or queries awaiting processing receive the noindex directive automatically. You can check the crawl date and data freshness directly on the result page.

Abuse protection

Before any network request, we validate the target to block private, loopback, link-local, multicast, and cloud metadata addresses — even if the provided domain resolves to one of those addresses after a redirect. We also apply rate limits per IP, per session, per tool, and per queried input, plus an anti-bot challenge (CAPTCHA or math challenge) on the forms.
