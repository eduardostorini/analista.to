What is hreflang?

Hreflang is an HTML attribute, used inside <link rel="alternate" hreflang="..."> tags in a page's <head> (it can also be declared via HTTP header or in an XML sitemap), that tells search engines which language and, optionally, which regional variant a page is written for, and which other URLs on the site are equivalent versions in other languages or regions. A site that publishes content in English, Brazilian Portuguese, and European Portuguese, for example, uses hreflang to link all three versions of the same page together, so that a search engine can serve the right one to each user based on their language and location settings rather than showing everyone the same default version, or worse, showing multiple competing translations as unrelated duplicate content. The {{ site_name }} Hreflang Checker fetches the submitted page, extracts every hreflang alternate tag it declares, and validates the setup against the most common requirements and pitfalls of international SEO.

How to interpret the result

Each row in the result table shows one declared alternate: its language/region code, whether that code follows a valid format, and the URL it points to. A valid code is either a bare language code such as en or pt, a language plus region such as pt-BR or en-US, or the special value x-default, which designates the fallback page to show when no other declared variant matches the user's language. The tool also flags three common configuration mistakes: duplicate codes (the same language/region declared more than once, which is contradictory and confuses crawlers about which URL is authoritative for that variant); a missing x-default when two or more language variants exist, which leaves undefined what should be shown to a visitor whose language does not match any of the declared alternates; and a missing self-reference, meaning the page you checked does not list itself among its own alternates — hreflang implementations require every page in a set to reference all other pages in the set, including itself.

Common use cases

International and multilingual sites use this tool before and after a translation rollout to confirm that every locale correctly cross-references its siblings, since a single broken or missing reciprocal link can quietly remove a whole language variant from consideration in search results for that market. E-commerce companies expanding into new countries use it to validate that country-specific storefronts (for example /us/, /uk/, /br/) are properly linked so that shoppers are matched to the correct currency and shipping region from search results. It is also a standard step in technical SEO audits for any site targeting more than one language, and useful when debugging reports that the "wrong" language version of a page is ranking in a particular country.

Limitations

This tool only reads hreflang tags declared as <link> elements in the raw HTML response; it does not execute JavaScript, so tags injected after page load by a client-side framework will not be detected, and it does not read hreflang annotations declared via HTTP headers (used mainly for non-HTML resources like PDFs) or inside XML sitemaps, which are the two other valid ways to declare hreflang. Crucially, this tool can only validate the page you submit — it cannot verify that the pages it points to reciprocally link back, since hreflang requires every page in a cluster to reference every other page, including itself. A complete audit means running this check on every URL in the language cluster and cross-referencing the results by hand or with a dedicated site-wide crawler.

Getting language and region codes right

A subtle but common error is confusing language codes with region codes, or using invalid or made-up combinations. Hreflang codes should follow ISO 639-1 for the language (two letters, such as en, pt, es) optionally followed by a hyphen and an ISO 3166-1 Alpha-2 region code (two letters, such as BR, US, MX). It is valid to target a language without a region (pt for all Portuguese speakers) or a language with a region (pt-BR specifically for Brazil), but it is invalid to specify a region without a language, and it is a common mistake to swap the order and write something like BR-pt instead of pt-BR. Search engines silently ignore hreflang tags with malformed codes rather than erroring loudly, which is exactly why an automated format check like this one is valuable — the mistake produces no visible symptom until you notice the expected audience simply is not being served the intended page.
