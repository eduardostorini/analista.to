What is an SSL/TLS certificate?

An SSL/TLS certificate is the digital document that allows a browser to confirm that it is really connecting to the expected domain, and that the communication between it and the server is encrypted. The certificate is issued by a Certificate Authority (CA) and contains, among other data, the domain(s) for which it is valid, the validity period, and the chain of trust up to a root CA recognized by browsers. This tool connects to the informed domain on port 443, obtains the certificate presented by the server, and organizes the most relevant information for quick verification.

How to interpret the result

The main indicator shows whether the certificate is valid, close to expiring (15 days or less), or expired — expired certificates cause browsers to display blocking security warnings to visitors, so this is a problem that requires immediate action. The "Untrusted chain" indicator appears when the certificate is self-signed, expired, or issued by a CA that browsers do not recognize — in those cases, we still show the certificate data, but visitors will see security warnings when accessing the site. The "Covered domains" (Subject Alternative Names, or SAN) list all names for which that single certificate is valid — it is common for a certificate to cover both example.com and www.example.com, and wildcard certificates cover any subdomain with a SAN in the format *.example.com.

Common use cases

Operations teams use this tool to proactively monitor the proximity of certificate expiration for critical certificates, avoiding unexpected availability outages (since browsers block normal access to sites with expired certificates). It is also used to confirm that a newly installed certificate covers all required domains, to diagnose security warnings reported by users, and to quickly audit the TLS configuration of vendors and partners before integrations.

Limitations

This tool checks only the certificate presented on port 443 — it does not evaluate other advanced TLS security aspects, such as which protocol versions and cipher suites the server accepts beyond what was negotiated in this specific connection, nor does it perform a scan for known vulnerabilities. For a broader analysis of HTTP security headers (different from TLS certificate), use the Security Headers tool.

Certificate renewal automation

Most certificate-related outages today happen not from a lack of technical knowledge, but from process failures: certificates issued manually and forgotten until the expiration date. Modern certificate authorities, like Let's Encrypt, issue free certificates with short validity (90 days) precisely to encourage automated renewal through tools like Certbot, eliminating the human factor from the process. If your organization still depends on manual renewal, the first practical step after using this tool is to set up a continuous monitoring alert — not just point-in-time checks — to never again be surprised by an expired certificate in production.

HTTPS beyond the lock icon

Having a valid certificate is today a minimum requirement, not a differentiator: modern browsers actively mark sites served over plain HTTP as "not secure," and Google itself uses HTTPS as a ranking signal, even if a minor one. Beyond the visual trust of the lock icon, HTTPS protects the integrity of data transmitted between visitor and server against interception and modification by intermediate networks — something especially relevant on public Wi-Fi connections. For this reason, even sites that do not handle passwords or payments directly benefit from keeping the certificate always valid and properly configured.
