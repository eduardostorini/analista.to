What is a canonical tag?

A canonical tag is an HTML element, <link rel="canonical" href="...">, placed in the <head> of a page to tell search engines which URL should be treated as the authoritative, "master" version of that content. Canonicalization matters because the same content is very often reachable through more than one URL — with and without trailing slash, with tracking parameters, through HTTP and HTTPS, via www and non-www hosts, or through faceted navigation and sorting parameters on e-commerce category pages. Without a clear signal, a search engine has to guess which of these variants deserves to rank, and it may split ranking signals like backlinks and engagement across several URLs instead of consolidating them onto one, which weakens the page's ability to compete in search results. The {{ site_name }} Canonical URL Checker fetches the page you submit, looks for every <link rel="canonical"> tag present in the HTML, and reports whether the setup follows recommended practice.

How to interpret the result

When exactly one canonical tag is found, the tool checks whether it points back to the same URL that was requested (a "self-referencing" canonical) or to a different URL. A self-referencing canonical is the normal, expected state for most standalone pages, and is itself considered good practice even when there is no known duplicate — it removes any ambiguity for crawlers. A canonical pointing to a different URL is not automatically wrong: it is exactly how you tell search engines to consolidate a duplicate or near-duplicate page (for example, a printer-friendly version, a paginated listing, or a URL variant with tracking parameters) into the "real" page. The tool simply flags this so you can confirm it was intentional. Finding zero canonical tags means the page leaves the decision entirely to the search engine's own heuristics, which is risky for content with known duplicates. Finding more than one canonical tag is always an error: per the specification only the first one encountered is considered, and having several is a sign of a templating bug, a plugin conflict, or manual and automated tags colliding on the same page.

Common use cases

SEO teams run this check after a site migration or a CMS change to confirm that canonical tags survived the move and still point at the correct final URLs, since template changes are a common source of dropped or duplicated canonical tags. E-commerce sites use it on category and filtered listing pages, where the same set of products can be reached through many sort-order and filter combinations, to verify that all of those variants canonicalize back to the clean, primary listing URL rather than being left to compete against each other. It is also useful when auditing a competitor's site structure, when debugging why a page is not being indexed as expected, and as a routine item in technical SEO audits alongside checks like meta tags, robots.txt, and sitemap validation.

Limitations

This tool only reads the canonical tag declared in the raw HTML response; it does not execute JavaScript, so a canonical tag injected client-side by a single-page application after the initial load will not be seen. It also does not verify whether the canonical target URL actually returns a 200 response, nor whether it is blocked by robots.txt or a noindex tag — a canonical pointing to a blocked or broken URL is a real but separate problem, best checked with the Broken Link Checker or Robots.txt Checker. Search engines also treat the canonical tag as a strong hint rather than an absolute directive: in cases of conflicting signals (such as internal links, sitemaps, and redirects pointing elsewhere), Google may choose a different URL than the one declared as canonical.

Canonical tags versus redirects

A frequent point of confusion is when to use a canonical tag versus a 301 redirect. A redirect is appropriate when the duplicate URL should no longer be reachable at all — users and crawlers are sent straight to the destination, and the old URL effectively stops existing as a separate page. A canonical tag is appropriate when both URLs need to remain independently accessible — for example, a product page reachable under two different category paths — but you still want search engines to treat them as one entity for ranking purposes. Using a canonical tag where a redirect would be more appropriate can leave low-value duplicate URLs crawlable indefinitely, wasting crawl budget on large sites; using a redirect where a canonical would be more appropriate can break legitimate use cases that depend on both URLs being independently reachable.
