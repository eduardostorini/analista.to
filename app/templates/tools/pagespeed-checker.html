What are Core Web Vitals?

Core Web Vitals are a set of metrics defined by Google to measure the real user experience of loading and interacting with a web page: Largest Contentful Paint (LCP) measures how long it takes for the largest visible element to render, Cumulative Layout Shift (CLS) measures visual stability (how much content unexpectedly moves around while loading), and Interaction to Next Paint (INP) measures responsiveness to user input. This tool runs the same Lighthouse engine used by Google's own PageSpeed Insights product against your URL, on a simulated mobile device and network, and reports both lab metrics (from the simulated run) and, when available, real-user field data aggregated from the Chrome User Experience Report (CrUX).

How to interpret the result

The performance score (0–100) is a weighted combination of several lab metrics and is a useful single-number summary, but the individual metrics below it are what actually drive user experience and search ranking signals. An LCP above 2.5 seconds, a CLS above 0.1, or a Total Blocking Time above 200ms are each individually flagged because they cross Google's documented "needs improvement" thresholds. Field data, when available, reflects what real visitors experienced over the past 28 days and is generally more trustworthy than a single lab run, which only reflects one simulated device and network condition — a page can score well in the lab while real users on slower devices or networks have a noticeably worse experience.

Common use cases

This tool is used to validate that a performance optimization actually moved the needle before and after a deploy, to investigate a drop in Google Search ranking that may correlate with a Core Web Vitals regression, to prioritize which of several possible optimizations (image compression, render-blocking script removal, font loading strategy) will have the largest measurable impact using the "estimated savings" figures, and to get a second opinion independent of browser DevTools when debugging perceived slowness reported by users.

Limitations

Field data is only available for URLs with sufficient real-user traffic in the CrUX dataset — low-traffic pages will show lab data only, which is clearly indicated in the result. Lab results can also vary run-to-run due to the inherent variability of network simulation and server load at the moment of the test; a single run should be treated as a representative sample, not an absolute number, and this tool intentionally caches results for two hours to avoid over-querying the same URL. Google's PageSpeed Insights API also shares a public quota when no API key is configured — during periods of high demand a request may time out, in which case the tool reports this clearly rather than fabricating a score.

Mobile vs. desktop

This tool always analyzes the mobile experience, since Google's indexing and ranking are mobile-first and mobile devices typically have less CPU power and less reliable network conditions than desktops — a page that performs well on mobile will almost always also perform well on desktop, but the reverse is frequently not true. If you need a desktop-specific analysis, running Lighthouse directly in Chrome DevTools with the desktop device preset is currently the most direct way to get that view; a dedicated desktop strategy option for this tool may be added in a future update.
