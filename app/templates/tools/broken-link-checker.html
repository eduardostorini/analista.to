What is a broken link check?

A broken link is a hyperlink that, when followed, no longer leads to a working page — the server responds with a client error such as 404 Not Found, or a server error such as 500 Internal Server Error, instead of returning the expected content. Links break for many mundane reasons: a page was deleted or moved without a redirect, a typo crept into the href attribute, an external site the page linked to was reorganized or taken offline, or a domain expired. Broken links degrade the experience for real visitors, who hit a dead end instead of the content they expected, and they also waste the crawl budget search engines allocate to a site, since crawlers follow links to discover and re-evaluate pages. The {{ site_name }} Broken Link Checker fetches the page you submit, extracts every outbound hyperlink it finds, and checks each one to report which are healthy and which are broken.

How to interpret the result

Each row in the result table shows one link found on the page, the HTTP status code its destination returned, and a category: "ok" for a normal 2xx success response, "redirect" for a 3xx response that forwards to another URL, "broken" for a 4xx or 5xx error response, "blocked" for a link the tool declined to follow because it resolved to a private or otherwise disallowed network address, and "error" for a link that could not be reached at all due to a timeout, connection failure, or similar network issue. The "scope" column distinguishes internal links (pointing to the same host as the page you checked) from external links (pointing elsewhere) — internal broken links are usually a more urgent fix, since they are entirely within your control, while external broken links depend on a third-party site and may resolve themselves, or may need to be updated or removed on your end.

Common use cases

Content and editorial teams run this check on important landing pages and cornerstone articles periodically, since links that were valid when a page was published can silently rot over months or years as linked resources move or disappear. Web developers use it after a site migration or a large content restructuring to catch internal links that were not updated to match new URL patterns. SEO practitioners use it as part of a broader technical audit, since a page riddled with broken internal links signals poor maintenance to both users and search engines, and can waste crawl budget on large sites. It is also useful before a scheduled content refresh, to identify which outbound citations and resource links on an older page need to be updated or removed before republishing.

Limitations

This tool checks only the links found on the single page you submit — it is not a full-site crawler, and it will not discover or check links on other pages of the site unless you submit each page individually. To keep response times reasonable and to avoid becoming a vector for abuse (issuing large numbers of outbound requests on someone else's behalf), the scan is capped to the first 15 links found and to a fixed time budget; on pages with many links, the result will indicate a partial scan and only the earliest links encountered in the HTML will have been checked. This tool also uses lightweight HEAD requests (falling back to GET only when a server rejects HEAD) rather than rendering the destination page, so it cannot detect "soft 404s" — pages that return a 200 OK status but display a human-readable "page not found" message instead of a proper error code.

Why some links show as blocked

For safety, this tool never follows a link whose destination resolves to a private, loopback, link-local, or otherwise internal network address — the same protection that governs every fetch this platform performs on a user-supplied URL. A link like this being present on a real public page is uncommon but not impossible: it can happen with a stale internal URL accidentally left in published content, a broken CMS template that generates an internal path by mistake, or a link intended only for an internal audience. A "blocked" result does not necessarily mean the destination is broken — the tool simply never attempted to reach it — but it is usually still worth investigating, since a public page linking to an internal-only address is rarely intentional.
