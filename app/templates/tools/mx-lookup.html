What is MX Lookup?

MX (Mail Exchanger) records are the mechanism by which DNS tells any email server in the world where to send messages destined for a domain. When someone sends an email to contact@example.com, the sending server first queries the MX records of example.com to discover which server is authorized to receive that message — only then does the actual delivery happen. The MX Lookup of {{ site_name }} queries these records and organizes them by priority, showing exactly which servers are configured to receive email on behalf of the informed domain.

How to interpret the result

Each MX record has a priority value (also called "preference"): the lower the number, the higher the priority. Sending servers try the record with the lowest value first; if it does not respond, they try the next in ascending order. It is common to see two or more MX records with different priorities — this is exactly a redundancy configuration, so the domain continues receiving email even if the primary server is unavailable. When the result shows "no email server configured," it means the domain cannot receive emails directly — which is normal for domains used only for institutional websites without their own mailbox, but it is a serious problem if you expected that domain to receive messages.

Common use cases

MX Lookup is the first stop when diagnosing "my email isn't arriving": it quickly confirms whether the domain is actually configured to receive messages and which provider (Google Workspace, Microsoft 365, Zoho, custom server, etc.) the traffic is being directed to. It is also useful when migrating from one email provider to another — after changing the MX records at your DNS provider, you can confirm here whether the change is already publicly visible before considering the migration complete. Also, knowing which provider a third-party domain points its email to helps in phishing investigations and competitive analysis (e.g., identifying whether a company uses Google Workspace or its own infrastructure).

Limitations

Like any DNS query, the values shown reflect the current state visible to the resolvers used by {{ site_name }} and may take some hours to reflect recent changes due to record TTL caching. MX Lookup does not verify whether the listed email server is actually functioning or accepting connections — only that it is declared as responsible for the domain. For deeper delivery issue diagnosis, combine this tool with the SPF Checker and DMARC Checker.

MX and the email delivery journey

It is worth understanding the role of MX within the complete email delivery flow: first, the sending server queries the MX of the destination domain to know where to send; then it connects to that server and attempts delivery; finally, authentication mechanisms like SPF, DKIM, and DMARC come into play to validate whether the sender was in fact authorized to send on behalf of the origin domain. MX handles only the first step — "where to deliver" — and has no direct relationship with the authentication of the sender. Therefore, a domain can have a perfectly configured MX and still suffer from email deliverability issues for emails sent from it, if SPF, DKIM, or DMARC are absent or misconfigured in the sending domains.
