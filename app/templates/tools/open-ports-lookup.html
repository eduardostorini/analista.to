What is Open Ports Lookup?

Every network service running on a server — a website, a database, a mail server, a remote access tool — listens on a specific TCP port, and a firewall or router in front of it decides which of those ports the outside world is allowed to reach. This tool checks a curated list of roughly 85 well-known ports against a domain or IP address using a real TCP connect scan — attempting an actual three-way TCP handshake against each port, the same technique behind an unprivileged nmap -sT scan — and reports which ones accepted a connection ("open") and which refused or ignored it ("closed"). Each port is shown alongside a short description of what it is most commonly used for, so results are readable without needing to memorize a list of protocol numbers.

How to interpret the result

"Open" means something on the server actively accepted the TCP connection — a real service is listening there, whether that is expected (port 443 open on a web server) or a potential concern (a database port like 3306 or 5432 open to the entire internet, or an old admin panel nobody remembers enabling). "Closed" means the connection was actively refused, and in many setups a firewalled port will behave identically to a closed one from this test's perspective, since both simply fail to establish a connection. Having many open ports is not inherently bad — it depends entirely on what each one is and whether it is meant to be reachable publicly — but any open port you do not recognize is worth investigating immediately.

Common use cases

System administrators use this after configuring a firewall to confirm it actually blocks what it is supposed to block, since a misconfigured rule is invisible until something exposes it. Security-conscious site owners run it periodically on their own infrastructure to catch services that were opened temporarily for maintenance and never closed again — a very common way internal databases and admin tools end up exposed to the internet by accident. It is also useful before deploying a new server, confirming that only the intended ports (typically 80 and 443) are reachable, and during incident response, quickly checking whether a compromised host has an unexpected backdoor port open — several ports in this list, like 12345, 27374, and 31337, are historically associated with well-known Windows trojans precisely for this reason.

Limitations

This is a TCP connect scan, not a full network audit: it only tests the specific list of ports shown here, not the entire 0-65535 range, and it only tests TCP, not UDP, which services like DNS, DHCP, and many VPNs also rely on. A port can appear closed here while still being reachable from other network locations, since some firewalls allow specific source IPs or block based on geography — this scan only reflects what is reachable from our servers, at this specific moment. It also does not identify the exact software or version behind an open port, only that something is listening. Finally, only run this against systems you own or have explicit authorization to test — scanning infrastructure you do not control without permission can violate the target's terms of service or, depending on jurisdiction, the law.
