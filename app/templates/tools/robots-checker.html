O que é o robots.txt?

O arquivo robots.txt, publicado na raiz de um domínio (por exemplo, exemplo.com.br/robots.txt), é a forma padronizada de um site comunicar a rastreadores automáticos — como o Googlebot — quais áreas podem ou não ser visitadas. Ele segue o Robots Exclusion Protocol: cada bloco começa com uma ou mais linhas User-agent (identificando a qual rastreador as regras seguintes se aplicam, sendo * um coringa para todos) seguidas de diretivas Disallow (caminhos bloqueados) e Allow (exceções dentro de um caminho bloqueado). O arquivo também pode declarar a localização de um ou mais sitemaps XML, ajudando buscadores a descobrir todas as URLs importantes do site mais rapidamente.

Como interpretar o resultado

Se o domínio não tiver um robots.txt, isso não é um erro — significa apenas que não há restrição declarada, e rastreadores assumem que podem visitar qualquer caminho público. Cada grupo exibido no resultado corresponde a um bloco User-agent do arquivo; preste atenção especial a blocos com User-agent: * e Disallow: /, que bloqueiam o site inteiro para todos os rastreadores — geralmente um erro de configuração grave se o site deveria estar sendo indexado normalmente, mas também uma configuração intencional em ambientes de staging/homologação. Diretivas Allow dentro de um bloco funcionam como exceções a um Disallow mais amplo, permitindo liberar um subcaminho específico dentro de uma área bloqueada.

Casos de uso comuns

Esta ferramenta é usada para confirmar que um ambiente de produção não está acidentalmente bloqueando os rastreadores (um erro comum ao promover configurações de staging), para verificar se o sitemap está corretamente declarado e apontando para a URL certa, para auditar rapidamente quais áreas de um site concorrente estão fechadas para indexação, e para diagnosticar por que páginas específicas não aparecem no Google mesmo estando publicadas — um Disallow mal configurado é uma das causas mais comuns.

Limitações

O robots.txt é uma convenção respeitada voluntariamente pela grande maioria dos rastreadores de boa reputação, mas não é um mecanismo de segurança — ele não impede acesso humano direto nem rastreadores maliciosos que optam por ignorá-lo. Bloquear uma página via robots.txt também não garante que ela não apareça no índice do Google: se outras páginas linkarem para ela, o Google pode ainda listar a URL (sem descrição) nos resultados. Para impedir indexação de forma garantida, combine ou substitua o bloqueio no robots.txt por uma tag meta robots="noindex" na própria página.

Erros comuns de configuração

Um dos erros mais custosos envolvendo robots.txt acontece durante a promoção de um ambiente de homologação para produção: é comum que ambientes de teste tenham um bloqueio total (Disallow: /) para evitar que buscadores indexem conteúdo ainda não pronto, e esse arquivo acaba sendo copiado sem alteração para o ambiente de produção, bloqueando acidentalmente o site inteiro. Outro erro frequente é bloquear caminhos que hospedam recursos necessários para a renderização da página, como pastas de CSS ou JavaScript — isso pode impedir que buscadores processem corretamente o layout e o conteúdo real da página. Por isso, sempre que uma página importante parar de aparecer nos resultados de busca, checar o robots.txt deveria ser um dos primeiros passos do diagnóstico.
