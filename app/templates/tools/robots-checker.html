What is robots.txt?

The robots.txt file, published at the root of a domain (for example, example.com/robots.txt), is the standardized way for a site to communicate to automated crawlers — such as Googlebot — which areas may or may not be visited. It follows the Robots Exclusion Protocol: each block starts with one or more lines User-agent (identifying which crawler the following rules apply to, with * a wildcard for all) followed by directives Disallow (blocked paths) and Allow (exceptions within a blocked path). The file may also declare the location of one or more XML sitemaps, helping search engines discover all important URLs on the site more quickly.

How to interpret the result

If the domain does not have a robots.txt, that is not an error — it simply means there is no declared restriction, and crawlers assume they can visit any public path. Each group displayed in the result corresponds to a User-agent block in the file; pay special attention to blocks with User-agent: * and Disallow: /, which block the entire site for all crawlers — usually a serious configuration error if the site should be indexed normally, but also an intentional configuration in staging/testing environments. Allow directives within a block work as exceptions to a broader Disallow, allowing a specific subpath within a blocked area to be freed.

Common use cases

This tool is used to confirm that a production environment is not accidentally blocking crawlers (a common error when promoting staging configurations), to verify that the sitemap is correctly declared and pointing to the right URL, to quickly audit which areas of a competitor's site are closed from indexing, and to diagnose why specific pages do not appear in Google even when published — a misconfigured Disallow is one of the most common causes.

Limitations

robots.txt is a convention voluntarily respected by the vast majority of reputable crawlers, but it is not a security mechanism — it does not prevent direct human access nor malicious crawlers that choose to ignore it. Blocking a page via robots.txt also does not guarantee that it will not appear in Google's index: if other pages link to it, Google may still list the URL (without description) in results. To guarantee blocking of indexing, combine or replace the robots.txt block with a meta robots="noindex" tag on the page itself.

Common configuration errors

One of the costliest errors involving robots.txt happens during the promotion of a testing environment to production: it is common for test environments to have a total block (Disallow: /) to prevent search engines from indexing unfinished content, and that file ends up being copied unchanged to the production environment, accidentally blocking the entire site. Another frequent error is blocking paths that host resources necessary for page rendering, such as CSS or JavaScript folders — this can prevent search engines from correctly processing the page's actual layout and content. Therefore, whenever an important page stops appearing in search results, checking robots.txt should be one of the first diagnostic steps.
