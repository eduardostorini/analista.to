What is DNS Lookup?

DNS (Domain Name System) is the system that translates human-readable domain names like example.com into information that servers and applications use to communicate — the most well-known is the IP address, but DNS carries much more than that. The {{ site_name }} DNS Lookup queries, in a single analysis, the seven most commonly used record types for domain administration: A (IPv4 address), AAAA (IPv6 address), MX (mail servers), TXT (verification, SPF, and other arbitrary strings), NS (nameservers responsible for the domain), CNAME (aliases for another name), and SOA (administrative zone data, such as the primary server and the refresh interval). Instead of running seven separate dig or nslookup commands, you get everything organized in a single table.

How to interpret the result

If the domain has no responding nameservers (NS), it is treated as having no active DNS delegation — which typically means the domain is not registered, has been removed, or the zone has not yet been published by the registrar. When the domain exists, each table row shows the record type and the values found; types with no records appear with a dash, which is normal — not every domain needs, for example, an AAAA (IPv6) or MX (email) record. Pay special attention to the NS: if the nameservers shown are not what you expected (e.g., still pointing to the registrar instead of your hosting provider), this usually indicates that the DNS migration is not complete or that propagation is still in progress. Multiple A records generally indicate load balancing across multiple servers; a CNAME should never coexist with other records at the same name, so if you expected to see a CNAME but did not find it alongside other types, review the zone configuration.

Common use cases

This tool is useful for confirming that a hosting or email provider migration has propagated, for diagnosing why a site is not accessible, for quickly auditing the DNS configuration of a third-party domain before an integration, or simply for understanding how a domain is structured without needing to install command-line tools. Support teams also use DNS Lookup as the first step when investigating "the site won't open" or "email isn't arriving" complaints, since many of these problems stem from incorrect or outdated DNS records.

Limitations

The results reflect what the public DNS servers queried by {{ site_name }} see at the time of the query. Because DNS is distributed and uses cache (TTL) at multiple layers, it is possible that different resolvers around the world still show old values for some hours after a change — this phenomenon is called DNS propagation. If you just changed a record and it does not yet appear updated here, wait for the TTL configured in the zone (typically between a few minutes and a few hours) and try again.
