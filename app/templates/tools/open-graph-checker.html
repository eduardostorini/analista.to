What is the Open Graph Checker?

Open Graph is a protocol originally created by Facebook that allows any webpage to become a rich object in a social graph. When a URL is shared on Facebook, Twitter, LinkedIn, WhatsApp, or other platforms, the platform looks for Open Graph meta tags in the HTML to decide what title, description, image, and other metadata to display in the preview card. The Open Graph Checker fetches any URL and extracts every og:* tag it finds, giving you a clear view of how that page will look when shared. This is essential for SEO, social media marketing, and content debugging because a missing or poorly crafted Open Graph tag can make a shared link look broken, generic, or unappealing, reducing click-through rates and engagement even if the underlying content is excellent.

How to interpret the result

The result shows each Open Graph property found on the page. The most important ones are og:title, og:description, og:image, and og:url. og:title should be a compelling headline, usually between 40 and 60 characters, that makes sense out of context. og:description should summarize the content in one or two sentences, typically under 200 characters, and entice the user to click. og:image is the most visually impactful tag: it should be a high-quality image, at least 1200 by 630 pixels for best results on most platforms, and it must be accessible publicly so crawlers can fetch it. og:url should be the canonical URL of the page, helping social platforms consolidate likes and shares. Other useful tags include og:type, which tells the platform whether this is a website, article, video, or product; og:site_name, which controls the site name shown below the title; and og:locale, which sets the language and region. If any of these tags are missing, platforms will fall back to guessing from the generic HTML title, meta description, or images on the page, which often produces worse results than providing explicit Open Graph data.

Common use cases

Social media managers use this tool to audit how their content looks before publishing, ensuring that every blog post, product page, or landing page has the correct title, description, and image when shared. SEO professionals use it during site launches or migrations to verify that Open Graph tags were correctly transferred to the new CMS or template. Developers use it to debug cases where a shared link shows the wrong image or an outdated description, which is often caused by caching, missing tags, or incorrect image dimensions. Content teams use it to preview how an article will appear on LinkedIn or Twitter, adjusting the tags to match the tone and messaging of the campaign. Support teams use it to answer client questions about why a page preview looks broken or generic, pointing directly to missing or malformed og:tags. It is also useful for competitive analysis: by checking a competitor's Open Graph setup, you can see how they structure their social previews and whether their images follow the recommended dimensions for maximum visibility.

Limitations

This tool only inspects the static Open Graph tags present in the HTML source. It does not execute JavaScript, so it cannot see dynamically injected tags added by client-side frameworks after page load. It also does not validate whether the og:image URL is accessible, correctly sized, or has the right aspect ratio — it only reports the URL declared in the tag. Some platforms support extended namespaces like article:author or video:url, which this tool may not list if they use non-standard prefixes. Finally, social platforms cache shared previews aggressively, sometimes for days or weeks, so changing Open Graph tags on a live page may not immediately update the preview seen by users. In those cases, you may need to use platform-specific debug tools like Facebook's Sharing Debugger or LinkedIn's Post Inspector to force a refresh.
